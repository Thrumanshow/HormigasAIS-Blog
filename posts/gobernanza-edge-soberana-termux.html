Gobernanza Edge Soberana: Administrando Workers sin Wrangler en Termux

Publicado por Cristhiam Leonardo Hernández Quiñonez (CLHQ) · Agosto 2026 · Nodo A16-SanMiguel-SV

En el desarrollo tradicional para Cloudflare Workers, la industria asume la necesidad de CLI oficiales como wrangler. Sin embargo, en entornos móviles de borde (Android/Termux ARM64), la emulación local de miniflare/workerd falla debido a la ausencia de entorno glibc.

1. Causa Raíz: Incompatibilidad Bionic vs. glibc

Al ejecutar emulación local (npx wrangler dev v3.x bajo Node.js v20+ ARM64), Wrangler intenta arrancar el binario precompilado de workerd. Al estar enlazado dinámicamente contra GNU glibc, la ejecución colapsa en la biblioteca C nativa de Android (bionic).

Error de emulación local en Termux ARM64:
$ npx wrangler dev
[ERROR] Failed to start workerd: Error: /data/data/com.termux/files/usr/lib/libc.so: version 'GLIBC_2.34' not found

2. Despliegue Directo vía API REST v4 (Multipart)

Eludimos la necesidad del entorno de emulación local subiendo el bundle JS directamente al plano de control de Cloudflare mediante la API v4 estructurada en multipart/form-data.

# A. Subida del bundle del Worker (ES Modules)
curl --fail-with-body --silent --show-error \
  -X PUT "https://api.cloudflare.com/client/v4/accounts/$CF_ACCOUNT_ID/workers/scripts/$CF_WORKER_NAME/content" \
  -H "Authorization: Bearer $CF_API_TOKEN" \
  -F 'metadata={"main_module":"worker.js"};type=application/json' \
  -F 'worker.js=@dist/worker.js;type=application/javascript+module'

# B. Inyección atómica y segura de secretos al Edge (evitando interpolación directa)
SECRET_PAYLOAD=$(jq -n --arg val "$VALUE" '{"name":"MASTER_SEAL_KEY","text":$val,"type":"secret_text"}')

curl -s -X PUT "https://api.cloudflare.com/client/v4/accounts/$CF_ACCOUNT_ID/workers/scripts/$CF_WORKER_NAME/secrets" \
  -H "Authorization: Bearer $CF_API_TOKEN" \
  -H "Content-Type: application/json" \
  --data "$SECRET_PAYLOAD"

3. Modelo Criptográfico: Firma Local vs. Verificación en Edge

Es indispensable distinguir entre la custodia de llaves y la firma de paquetes:

  • Firma Local (Nodo Soberano): Los payloads LBH se firman criptográficamente dentro del dispositivo Termux utilizando la clave privada almacenada en ~/.hormigas_secrets (protegido con permisos 0600 y sandboxing UID de Android).
  • Verificación Edge (Cloudflare Worker): El Worker en el Edge almacena únicamente el secreto de verificación para validar la autenticidad del paquete recibido antes de procesarlo, manteniendo la clave de origen aislada en el nodo.
