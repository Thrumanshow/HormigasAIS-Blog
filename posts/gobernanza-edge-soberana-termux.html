Gobernanza Edge Soberana: Administrando Workers sin Wrangler en Termux

Publicado por Cristhiam Leonardo Hernández Quiñonez (CLHQ) · Agosto 2026 · Nodo A16-SanMiguel-SV

En el desarrollo tradicional para Cloudflare Workers, la industria asume la necesidad de entornos x86_64 o CLI oficiales como wrangler. Sin embargo, en entornos móviles de borde (Android/Termux ARM64), el flujo estándar falla debido a incompatibilidades de enlazado dinámico en las capas inferiores del sistema operativo.

1. El Cuyo Técnico: Incompatibilidad Bionic vs. glibc

El CLI oficial de Wrangler descarga binarios precompilados del motor workerd (basado en V8). Estos binarios están construidos para distribuciones Linux estándar vinculadas a GNU glibc. Termux opera sobre el entorno nativo de Android, cuya biblioteca C es bionic.

Error característico en Termux:
$ npx wrangler dev
[ERROR] Failed to start workerd: Error: /data/data/com.termux/files/usr/lib/libc.so: version 'GLIBC_2.34' not found

2. Desacoplamiento vía API REST v4

Para eludir la barrera de compilación, reemplazamos la abstracción de Wrangler por el plano de control directo de la API REST v4 de Cloudflare usando HTTP y POSIX Shell.

# A. Subida directa del bundle JavaScript (worker.js)
curl -s -X PUT "https://api.cloudflare.com/client/v4/accounts/$CF_ACCOUNT_ID/workers/scripts/$CF_WORKER_NAME" \
  -H "Authorization: Bearer $CF_API_TOKEN" \
  -H "Content-Type: application/javascript" \
  --data-binary "@dist/worker.js"

# B. Inyección atómica de secretos al Edge
curl -s -X PUT "https://api.cloudflare.com/client/v4/accounts/$CF_ACCOUNT_ID/workers/scripts/$CF_WORKER_NAME/secrets" \
  -H "Authorization: Bearer $CF_API_TOKEN" \
  -H "Content-Type: application/json" \
  --data "{\"name\":\"MASTER_SEAL_KEY\",\"text\":\"$VALUE\",\"type\":\"secret_text\"}"

3. Aislamiento Criptográfico en Dispositivos Móviles

En lugar de delegar el manejo de claves secretas a entornos de desarrollo de terceros, las claves maestras (LBH_SECRET) se resguardan localmente en ~/.hormigas_secrets protegido con permisos 0600 (POSIX DAC) y bajo el sandboxing estricto por UID de Android. Si bien no constituye un HSM basado en hardware (TEE), este esquema garantiza que la firma criptográfica permanezca bajo control local directo antes de su transmisión cifrada al Edge.
